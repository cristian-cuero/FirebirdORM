# Referencia Técnica de la API - firebird-orm

Guía exhaustiva para desarrolladores que necesitan dominar cada aspecto del ORM: configuración, modelos, tipos de datos, consultas, relaciones y extensibilidad.

---

## 1. Instancia Principal: `Sequelize`

### Constructor
```javascript
import { Sequelize } from 'firebird-orm';

const sequelize = new Sequelize(config);
```

### Objeto de Configuración (`config`)

| Parámetro | Tipo | Requerido | Default | Descripción |
| :--- | :--- | :--- | :--- | :--- |
| `host` | `string` | ✅ | - | IP o hostname del servidor Firebird. |
| `port` | `number` | ❌ | `3050` | Puerto TCP (3050 estándar, 3053 FB 2.5 clásico). |
| `database` | `string` | ✅ | - | Ruta absoluta al archivo `.fdb` en el servidor. |
| `user` | `string` | ✅ | - | Usuario (ej. `SYSDBA`). |
| `password` | `string` | ✅ | - | Contraseña. |
| `pool` | `object` | ❌ | ver abajo | Configuración del pool de conexiones. |
| `dialectOptions` | `object` | ❌ | `{}` | Opciones específicas del dialecto Firebird. |
| `logging` | `function\|boolean` | ❌ | `false` | Función `(sql, params, duration) => {}` o `true` (console.log). |
| `benchmark` | `boolean` | ❌ | `false` | Mide tiempo de ejecución de queries. |

#### Configuración del Pool (`pool`)
```javascript
pool: {
  min: 0,              // Mínimo conexiones abiertas
  max: 10,             // Máximo conexiones concurrentes
  idle: 10000,         // Ms antes de cerrar conexión inactiva
  acquire: 30000,      // Ms max esperando conexión libre
  evictionRunIntervalMillis: 15000 // Intervalo limpieza conexiones zombies
}
```

#### Opciones de Dialecto (`dialectOptions`)
```javascript
dialectOptions: {
  forceVersion: '3.0', // Forzar versión: '2.5', '3.0', '4.0', '5.0' (skip auto-detect)
  // Opciones futuras: charset, timezone, etc.
}
```

### Métodos de Instancia

| Método | Retorno | Descripción |
| :--- | :--- | :--- |
| `init()` | `Promise<void>` | **Obligatorio**. Conecta, detecta versión FB y valida capacidades. |
| `define(name, attrs, opts)` | `Model` | Define y registra un modelo. |
| `queryRaw(sql, opts)` | `Promise<Array>` | Ejecuta SQL nativo parametrizado (ver Sección 7). |
| `query(sql, params, opts)` | `Promise<Array>` | Alias legacy para `queryRaw`. |
| `close()` | `Promise<void>` | Cierra pool y libera recursos. |
| `transaction()` | `Promise<Transaction>` | Inicia transacción (ver Sección 5). |

### Propiedades de Instancia
*   `sequelize.version` (`string`): Versión detectada (ej. `'3.0.10'`).
*   `sequelize.dialect.capabilities` (`object`): Flags de features (`identityColumns`, `booleanType`, `returningClause`, `windowFunctions`).
*   `sequelize.models` (`object`): Registro de modelos definidos (`{ User: Model, ... }`).

## 2. Definición de Modelos (`sequelize.define`)

```javascript
const Model = sequelize.define('ModelName', attributes, options);
```

### 2.1 Definición de Atributos (`attributes`)

Cada clave es el nombre de la propiedad en **JavaScript (camelCase)**. El valor es un objeto de configuración:

```javascript
{
  // Nombre en JS: 'email'
  email: {
    type: DataTypes.STRING(100),   // Tipo de dato (ver Sección 3)
    field: 'EMAIL',                // Nombre real en BD (snake_case/UPPERCASE)
    primaryKey: false,             // ¿Es PK?
    allowNull: false,              // NOT NULL constraint + validación
    unique: true,                  // UNIQUE constraint + validación
    defaultValue: 'default@test.com', // Valor por defecto (DB + JS)
    validate: {                    // Validaciones JS (ver Sección 4)
      isEmail: true,
      len: [5, 100]
    },
    comment: 'Email del usuario',  // Comentario en DDL (CREATE TABLE)
    get() { return this.getDataValue('email').toLowerCase(); }, // Getter personalizado
    set(val) { this.setDataValue('email', val.trim()); } // Setter personalizado
  }
}
```

#### Opciones Comunes del Atributo
| Opción | Tipo | Descripción |
| :--- | :--- | :--- |
| `type` | `DataTypes` | **Obligatorio**. Ver Sección 3. |
| `field` | `string` | Nombre de columna en Firebird. Si omitido, se usa la clave del atributo (convertido según convención). |
| `primaryKey` | `boolean` | Marca como Primary Key. |
| `autoIncrement` | `boolean` | `GENERATED BY DEFAULT AS IDENTITY` (FB 3+) o Trigger/Generator (FB 2.5). Implica `primaryKey: true`. |
| `allowNull` | `boolean` | `false` = `NOT NULL` en DDL + validación automática antes de `save()`. Default: `true`. |
| `defaultValue` | `any` | Valor por defecto. Acepta literales, `DataTypes.NOW`, `DataTypes.LITERAL('GEN_ID(MY_GEN, 1)')`. |
| `unique` | `boolean\|string` | `true` o nombre del índice único. |
| `validate` | `object` | Reglas de validación (ver Sección 4). |
| `comment` | `string` | Comentario en `CREATE TABLE` (FB 3+). |
| `get` | `function` | Getter virtual. `this.getDataValue('prop')` para leer valor crudo. |
| `set` | `function` | Setter virtual. `this.setDataValue('prop', val)` para escribir valor crudo. |
| `references` | `object` | `{ model: 'OtherModel', key: 'id' }` para FK (usado en migraciones/associations). |

### 2.2 Opciones del Modelo (`options`)

```javascript
const User = sequelize.define('User', { ... }, {
  // Tabla
  tableName: 'USUARIOS',          // Nombre exacto en Firebird
  freezeTableName: true,          // Evita pluralización/minúsculas automáticas
  
  // Timestamps automáticos
  timestamps: true,               // Añade createdAt / updatedAt (default: true)
  createdAt: 'CREATED_AT',        // Nombre real columna createdAt (requiere field)
  updatedAt: 'UPDATED_AT',        // Nombre real columna updatedAt (requiere field)
  
  // Validaciones a nivel de modelo (multi-campo)
  validate: {
    bothCoordsOrNone: true,       // Ejemplo custom validator
    isValidDomain: function() { ... }
  },
  
  // Hooks a nivel de modelo (ver Sección 6)
  hooks: { ... },
  
  // Índices (DDL)
  indexes: [
    { name: 'idx_user_email', unique: true, fields: ['email'] },
    { name: 'idx_user_active_name', fields: ['active', 'name'] }
  ],
  
  // Motor/Charset (Firebird específico)
  engine: undefined,              // No aplica en FB (solo MySQL)
  charset: 'UTF8',                // Charset por defecto de la tabla
  collate: 'UNICODE_CI_AI'        // Collation por defecto
});
```

#### Tabla Resumen Opciones Modelo
| Opción | Tipo | Default | Descripción |
| :--- | :--- | :--- | :--- |
| `tableName` | `string` | Nombre del modelo en minúsculas/plural | Nombre real tabla en BD. |
| `freezeTableName` | `boolean` | `false` | Si `true`, usa `tableName` literal. |
| `timestamps` | `boolean` | `true` | Añade `createdAt` / `updatedAt`. |
| `createdAt` | `string\|boolean` | `'createdAt'` | Nombre campo creación. `false` para desactivar solo este. |
| `updatedAt` | `string\|boolean` | `'updatedAt'` | Nombre campo actualización. `false` para desactivar solo este. |
| `indexes` | `Array` | `[]` | Definición de índices para `queryInterface.createTable`. |
| `hooks` | `object` | `{}` | Ciclo de vida global del modelo. |
| `validate` | `object` | `{}` | Validaciones multi-atributo. |

## 3. Tipos de Datos (`DataTypes`) - Mapeo Firebird ↔ JavaScript

**Regla de Oro:** `DECIMAL` / `NUMERIC` llegan a JS como **`string`** para preservar precisión exacta. Usa `parseFloat()`, `Number()` o librería `decimal.js` para operar.

| DataType | Firebird DDL | Tipo JS Entrada/Salida | Notas |
| :--- | :--- | :--- | :--- |
| `DataTypes.STRING(n)` | `VARCHAR(n)` | `string` | Requiere longitud `n`. |
| `DataTypes.CHAR(n)` | `CHAR(n)` | `string` | Rellena con espacios. |
| `DataTypes.TEXT` | `BLOB SUB_TYPE TEXT` | `string` | Texto largo (segmentos). |
| `DataTypes.INTEGER` | `INTEGER` | `number` | 32-bit signed. |
| `DataTypes.SMALLINT` | `SMALLINT` | `number` | 16-bit signed (usado para Booleanos legacy). |
| `DataTypes.BIGINT` | `BIGINT` | `number \| BigInt` | > 2^53 devuelve `BigInt`. |
| `DataTypes.DECIMAL(p, s)` | `DECIMAL(p, s)` | **`string`** | **Precisión exacta**. `p`=precisión, `s`=escala. |
| `DataTypes.NUMERIC(p, s)` | `NUMERIC(p, s)` | **`string`** | Alias de DECIMAL en FB. |
| `DataTypes.FLOAT` | `FLOAT` | `number` | 32-bit approx. |
| `DataTypes.DOUBLE` | `DOUBLE PRECISION` | `number` | 64-bit approx. |
| `DataTypes.DATE` | `DATE` | `Date` | Solo fecha (time 00:00:00 UTC). |
| `DataTypes.TIME` | `TIME` | `string` | Formato `HH:MM:SS.mmm`. |
| `DataTypes.DATEONLY` | `DATE` | `Date` | Alias semántico para DATE. |
| `DataTypes.TIMESTAMP` | `TIMESTAMP` | `Date` | Fecha + Hora con zona horaria. |
| `DataTypes.BOOLEAN` | `BOOLEAN` (FB 3+) / `SMALLINT` (FB 2.5) | `boolean` | Auto-adaptable según versión. |
| `DataTypes.BLOB('TEXT')` | `BLOB SUB_TYPE TEXT` | `string` | Lectura completa en memoria. |
| `DataTypes.BLOB('BINARY')` | `BLOB SUB_TYPE 0` | `Buffer` | Binario. |
| `DataTypes.UUID` | `CHAR(36)` | `string` | Generado en JS (`crypto.randomUUID()`). |
| `DataTypes.LITERAL(sql)` | `sql` | `any` | SQL crudo para `defaultValue` (ej. `CURRENT_TIMESTAMP`, `GEN_ID(...)`). |

### Uso de `DataTypes.LITERAL` (Generadores/Triggers Legacy FB 2.5)
```javascript
id: {
  type: DataTypes.INTEGER,
  primaryKey: true,
  // En FB 2.5 sin IDENTITY, usamos generador en defaultValue
  defaultValue: DataTypes.LITERAL('GEN_ID(GEN_USUARIOS_ID, 1)')
}
```

## 4. Validaciones

### 4.1 Validaciones por Atributo (Built-in)
Se definen dentro de `validate: {}` en el atributo.

| Validador | Uso | Descripción |
| :--- | :--- | :--- |
| `allowNull` | `false` | Ya definido en atributo, pero reforzable aquí. |
| `notNull` | `true` | Error si null/undefined. |
| `notEmpty` | `true` | Error si string vacío. |
| `isEmail` | `true` | Formato email. |
| `isUrl` | `true` | Formato URL. |
| `isIP` | `true` | Dirección IP. |
| `isAlpha` | `true` | Solo letras. |
| `isAlphanumeric` | `true` | Letras y números. |
| `isNumeric` | `true` | Solo números (string). |
| `isInt` | `true` | Entero válido. |
| `isFloat` | `true` | Float válido. |
| `isDecimal` | `true` | Decimal válido. |
| `isDate` | `true` | Fecha válida (Date u ISO string). |
| `isUUID` | `4` | UUID v4. |
| `len` | `[min, max]` | Longitud string/array. |
| `min` | `value` | Valor mínimo (numérico). |
| `max` | `value` | Valor máximo (numérico). |
| `equals` | `value` | Igualdad estricta (`===`). |
| `contains` | `substr` | Contiene subcadena. |
| `notContains` | `substr` | No contiene subcadena. |
| `isIn` | `[arr]` | Valor dentro de array. |
| `notIn` | `[arr]` | Valor fuera de array. |
| `is` | `/regex/` | Coincide regex. |
| `not` | `/regex/` | No coincide regex. |

### 4.2 Validadores Personalizados (Función)
```javascript
validate: {
  customRule(value) {
    if (value < 0) throw new Error('No puede ser negativo');
    if (value === 'FORBIDDEN') throw new Error('Valor prohibido');
  },
  async asyncRule(value) {
    const exists = await ExternalService.check(value);
    if (!exists) throw new Error('No existe en servicio externo');
  }
}
```

### 4.3 Validaciones a Nivel de Modelo (Multi-campo)
Se definen en `options.validate` del modelo. Reciben `this` (instancia).

```javascript
validate: {
  passwordMatch() {
    if (this.password !== this.passwordConfirm) {
      throw new Error('Las contraseñas no coinciden');
    }
  },
  startBeforeEnd() {
    if (this.startDate >= this.endDate) {
      throw new Error('Fecha inicio debe ser anterior a fin');
    }
  }
}
```

## 5. Consultas (Query Interface)

### 5.1 Métodos Estáticos del Modelo

| Método | Parámetros | Retorno | Descripción |
| :--- | :--- | :--- | :--- |
| `findAll(options)` | `FindOptions` | `Promise<Model[]>` | SELECT múltiple. |
| `findOne(options)` | `FindOptions` | `Promise<Model\|null>` | SELECT único (LIMIT 1). |
| `findByPk(pk, options)` | `pk, FindOptions` | `Promise<Model\|null>` | SELECT por Primary Key. |
| `findAndCountAll(options)` | `FindOptions` | `Promise<{count, rows}>` | Paginación: total + página. |
| `create(values, options)` | `object, CreateOptions` | `Promise<Model>` | INSERT + RETURNING. |
| `bulkCreate(records, options)` | `object[], BulkOptions` | `Promise<Model[]>` | INSERT masivo (eficiente). |
| `update(values, options)` | `object, UpdateOptions` | `Promise<[affectedCount]>` | UPDATE masivo. |
| `destroy(options)` | `DestroyOptions` | `Promise<affectedCount>` | DELETE masivo. |
| `count(options)` | `CountOptions` | `Promise<number>` | COUNT(*). |
| `sum(field, options)` | `string, Options` | `Promise<number>` | SUM(field). |
| `max(field, options)` | `string, Options` | `Promise<any>` | MAX(field). |
| `min(field, options)` | `string, Options` | `Promise<any>` | MIN(field). |

### 5.2 Objeto de Opciones (`FindOptions`, `CreateOptions`, etc.)

#### Comunes a todas
```javascript
{
  transaction: Transaction,      // Instancia de transacción activa
  logging: false \| fn,          // Override logging global
  benchmark: true,               // Override benchmark global
}
```

#### `FindOptions` (findAll, findOne, findAndCountAll)
```javascript
{
  // Filtros
  where: { ... },                // Ver Sección 6 (Operadores)
  
  // Proyección
  attributes: [
    'id',                        // Campo simple
    ['email', 'userEmail'],      // Alias: [campo, alias]
    [fn('COUNT', col('*')), 'total'], // Función SQL
    [literal('1'), 'one']        // Literal SQL
  ],
  // Si se omite: SELECT * (o columnas definidas en modelo)
  
  // Orden
  order: [
    ['name', 'ASC'],
    ['createdAt', 'DESC'],
    [fn('UPPER', col('name')), 'ASC']
  ],
  
  // Paginación (Adaptativa: LIMIT/OFFSET en FB 3+, FIRST/SKIP en FB 2.5)
  limit: 20,
  offset: 40,
  
  // Relaciones (Eager Loading)
  include: [
    {
      model: Pedido,
      as: 'pedidos',             // Alias definido en association
      required: false,           // true = INNER JOIN, false = LEFT JOIN
      where: { status: 'PENDING' }, // Filtro en la tabla relacionada
      attributes: ['id', 'total'],
      include: [ ... ]           // Anidado (N niveles)
    }
  ],
  
  // Agrupación
  group: ['active'],
  having: { active: 1 },         // Filtro post-group
  
  // Subconsultas / Raw
  raw: false,                    // true = devuelve POJOs, no instancias Model
  nest: false,                   // true = anida objetos planos (requiere raw:true)
  
  // Locking (FB 3+)
  lock: 'UPDATE',                // 'UPDATE' | 'SHARE' | 'NO KEY UPDATE' | 'KEY SHARE'
  skipLocked: true               // SKIP LOCKED
}
```

#### `CreateOptions` / `UpdateOptions` / `DestroyOptions`
```javascript
{
  fields: ['name', 'email'],     // Solo actualizar/insertar estos campos
  validate: true,                // Ejecutar validaciones (default: true)
  hooks: true,                   // Disparar hooks (default: true)
  returning: true,               // RETURNING * (FB 3+) - devuelve datos actualizados
  individualHooks: false,        // En bulkCreate: dispara hooks por fila
  ignoreDuplicates: false,       // ON CONFLICT DO NOTHING (PG) / MERGE (FB)
  onDuplicate: 'UPDATE'          // Estrategia duplicados (futuro)
}
```

## 6. Query Builder: Operadores y Funciones

### 6.1 Operadores (`Op`)
Importación: `import { Op } from 'firebird-orm';`

| Operador JS | SQL Generado | Ejemplo Uso |
| :--- | :--- | :--- |
| `Op.eq` | `=` | `{ id: { [Op.eq]: 1 } }` |
| `Op.ne` | `<>` | `{ id: { [Op.ne]: 1 } }` |
| `Op.gt` | `>` | `{ age: { [Op.gt]: 18 } }` |
| `Op.gte` | `>=` | `{ age: { [Op.gte]: 18 } }` |
| `Op.lt` | `<` | `{ age: { [Op.lt]: 65 } }` |
| `Op.lte` | `<=` | `{ age: { [Op.lte]: 65 } }` |
| `Op.like` | `LIKE` | `{ name: { [Op.like]: 'J%' } }` |
| `Op.iLike` | `ILIKE` (FB 3+) | `{ email: { [Op.iLike]: '%@GMAIL.COM' } }` |
| `Op.notLike` | `NOT LIKE` | `{ name: { [Op.notLike]: '%test%' } }` |
| `Op.in` | `IN (...)` | `{ id: { [Op.in]: [1,2,3] } }` |
| `Op.notIn` | `NOT IN (...)` | `{ id: { [Op.notIn]: [1,2,3] } }` |
| `Op.between` | `BETWEEN` | `{ age: { [Op.between]: [18, 65] } }` |
| `Op.notBetween` | `NOT BETWEEN` | `{ age: { [Op.notBetween]: [18, 65] } }` |
| `Op.is` | `IS` / `IS NULL` | `{ deletedAt: { [Op.is]: null } }` |
| `Op.not` | `IS NOT` / `IS NOT NULL` | `{ deletedAt: { [Op.not]: null } }` |
| `Op.and` | `AND` | `{ [Op.and]: [{a:1}, {b:2}] }` |
| `Op.or` | `OR` | `{ [Op.or]: [{a:1}, {b:2}] }` |
| `Op.col` | `columna` | `{ [Op.col]: 'user.name' }` (Comparar columnas) |

#### Lógica Implícita
```javascript
// Objeto raíz = AND implícito
where: {
  active: 1,           // AND
  age: { [Op.gt]: 18 } // AND
}
// Equivale a: WHERE active = 1 AND age > 18
```

### 6.2 Funciones SQL (`fn`, `col`, `literal`, `cast`)
Importación: `import { fn, col, literal, cast } from 'firebird-orm';`

#### `fn(name, ...args)` - Funciones Nativas Firebird
Genera `FUNCION(arg1, arg2, ...)`. Los args pueden ser strings (literales), `col()`, `fn()` anidados, `literal()`.

```javascript
// SELECT UPPER(name), COALESCE(phone, 'SIN DATOS')
attributes: [
  [fn('UPPER', col('name')), 'nameUpper'],
  [fn('COALESCE', col('phone'), 'SIN DATOS'), 'phone']
]

// WHERE: EXTRACT(YEAR FROM birth_date) = 1990
where: {
  [fn('EXTRACT', 'YEAR', col('birth_date'))]: 1990
}
```
**Funciones Firebird Comunes:** `UPPER`, `LOWER`, `TRIM`, `SUBSTRING`, `COALESCE`, `NULLIF`, `CAST`, `EXTRACT`, `DATEADD`, `DATEDIFF`, `CURRENT_DATE`, `CURRENT_TIMESTAMP`, `GEN_UUID`, `LIST` (aggregate).

#### `col(name)` - Referencia a Columna
Identificador seguro para columnas en `attributes`, `where`, `order`, `fn`.

```javascript
order: [[col('name'), 'ASC']]
where: { [col('price')]: { [Op.gt]: col('cost') } } // price > cost
```

#### `literal(sql)` - SQL Crudo (Cuidado)
Inyecta SQL directamente **sin parametrizar**. Úsalo solo para valores fijos o funciones del servidor sin parámetros de usuario.

```javascript
attributes: [
  [literal('CURRENT_TIMESTAMP'), 'now'],
  [literal('(SELECT COUNT(*) FROM PEDIDOS WHERE CLIENTE_ID = CLIENTES.ID)'), 'totalPedidos']
]
// ⚠️ NUNCA uses literals con input de usuario: literal(`name = '${input}'`) -> SQL INJECTION
```

#### `cast(expr, type)` - Conversión de Tipos
Genera `CAST(expr AS TIPO)`.

```javascript
attributes: [
  [cast(col('monto'), 'DECIMAL(15,2)'), 'montoExacto'],
  [cast(fn('SUM', col('total')), 'BIGINT'), 'sumTotal']
]
where: {
  [cast(col('fecha_str'), 'DATE')]: { [Op.gt]: '2023-01-01' }
}
```

## 7. SQL Nativo Seguro (`queryRaw`)

Para consultas imposibles con el ORM, SPs legacy, DDL, o migraciones.

### Firma
```javascript
sequelize.queryRaw(sql, options);
```

### Parámetros `options`
| Opción | Tipo | Descripción |
| :--- | :--- | :--- |
| `replacements` | `Array<any>` | **Array ordenado** de valores para placeholders `?`. **Obligatorio para seguridad**. |
| `transaction` | `Transaction` | Instancia de transacción activa. |
| `raw` | `boolean` | `true` (default): devuelve array de objetos planos. `false`: intenta mapear a modelos (raro). |
| `logging` | `function` | Override logger. |

### Ejemplos

#### 1. SELECT Parametrizado (Seguro)
```javascript
const users = await sequelize.queryRaw(
  'SELECT ID, NAME FROM USERS WHERE ACTIVE = ? AND AGE > ?',
  { replacements: [1, 18] } // Array posicional: coincide con los '?'
);
```

#### 2. Ejecutar Stored Procedure (Legacy VB6)
```javascript
// SELECT * FROM SP (retorna cursor)
const results = await sequelize.queryRaw(
  'SELECT * FROM SP_CALCULAR_SALDO(?, ?)',
  { replacements: [clienteId, fechaCorte] }
);

// EXECUTE PROCEDURE (acción, no retorna filas)
await sequelize.queryRaw(
  'EXECUTE PROCEDURE SP_ACTUALIZAR_STOCK(?, ?)',
  { replacements: [productoId, cantidad] }
);
```

#### 3. DDL Dinámico Seguro (Nombres de tabla/columna variables)
**Nunca concatene nombres de tabla/columna.** Use `SqlEscape.ident()`.

```javascript
import { SqlEscape } from 'firebird-orm';

const year = 2024;
const tableName = `VENTAS_${year}`; // Input controlado

const results = await sequelize.queryRaw(
  `SELECT * FROM ${SqlEscape.ident(tableName)} WHERE ${SqlEscape.ident('FECHA')} > ?`,
  { replacements: ['2024-01-01'] }
);
```
`SqlEscape.ident()` valida que el input sea alfanumérico/underscore y lo envuelve en comillas dobles (`"VENTAS_2024"`), protegiendo contra inyección en identificadores.

#### 4. Dentro de Transacción
```javascript
const t = await Transaction.start(sequelize);
try {
  await sequelize.queryRaw(
    'UPDATE CUENTAS SET SALDO = SALDO - ? WHERE ID = ?',
    { replacements: [100, 1], transaction: t }
  );
  await sequelize.queryRaw(
    'UPDATE CUENTAS SET SALDO = SALDO + ? WHERE ID = ?',
    { replacements: [100, 2], transaction: t }
  );
  await t.commit();
} catch (e) {
  await t.rollback();
  throw e;
}
```

## 8. Transacciones (`Transaction`)

### API
```javascript
import { Transaction } from 'firebird-orm';

// 1. Iniciar (Factory - Reserva conexión exclusiva del pool)
const tx = await Transaction.start(sequelize);

// 2. Usar en operaciones
await User.create({ name: 'Test' }, { transaction: tx });
await sequelize.queryRaw('...', { transaction: tx });

// 3. Confirmar o Revertir
await tx.commit();     // Libera conexión al pool
await tx.rollback();   // Libera conexión al pool
```

### Comportamiento Interno Crítico
1.  **Reserva Exclusiva**: `start()` saca una conexión física del pool y la marca como "en transacción". **Nadie más la usa**.
2.  **Aislamiento**:
    *   FB 3.0+: `SNAPSHOT` (Repeatable Read).
    *   FB 2.5: `READ COMMITTED`.
3.  **Limpieza Garantizada**: `commit()` y `rollback()` tienen bloque `finally` que llama a `connectionManager.releaseConnection()`. **No hay leaks**.
4.  **Timeouts**: Configurable via `pool.acquire` (espera conexión) y `dialectOptions.transactionTimeout` (futuro).

### Manejo de Deadlocks (Error -607 / 335544348)
```javascript
async function withRetry(fn, retries = 3) {
  try { return await fn(); }
  catch (err) {
    if (isDeadlock(err) && retries > 0) {
      await new Promise(r => setTimeout(r, 50 * (4 - retries))); // Backoff
      return withRetry(fn, retries - 1);
    }
    throw err;
  }
}

await withRetry(async () => {
  const tx = await Transaction.start(sequelize);
  try { ... await tx.commit(); }
  catch { await tx.rollback(); throw err; }
});
```

## 9. Hooks (Ciclo de Vida)

Permiten inyectar lógica antes/después de operaciones.

### 9.1 Definición
En `options.hooks` del modelo o `Model.addHook()`.

```javascript
const User = sequelize.define('User', { ... }, {
  hooks: {
    beforeValidate: (user, options) => { ... },
    afterValidate: (user, options) => { ... },
    
    beforeCreate: (user, options) => { ... },
    afterCreate: (user, options) => { ... },
    
    beforeUpdate: (user, options) => { ... },
    afterUpdate: (user, options) => { ... },
    
    beforeDestroy: (user, options) => { ... },
    afterDestroy: (user, options) => { ... },
    
    beforeSave: (user, options) => { ... },    // Create + Update
    afterSave: (user, options) => { ... },     // Create + Update
    
    beforeBulkCreate: (users, options) => { ... },
    afterBulkCreate: (users, options) => { ... },
    
    beforeBulkUpdate: (options) => { ... },
    afterBulkUpdate: (options) => { ... },
    
    beforeBulkDestroy: (options) => { ... },
    afterBulkDestroy: (options) => { ... },
  }
});
```

### 9.2 Argumentos del Hook
| Hook | Argumento 1 | Argumento 2 (`options`) |
| :--- | :--- | :--- |
| `beforeCreate` / `afterCreate` | `instance` (nueva) | `{ transaction, fields, hooks, ... }` |
| `beforeUpdate` / `afterUpdate` | `instance` (modificada) | `{ transaction, fields, where, ... }` |
| `beforeDestroy` / `afterDestroy` | `instance` (a borrar) | `{ transaction, where, ... }` |
| `beforeBulk...` | `Array<instance>` u `options` | `{ transaction, where, ... }` |

### 9.3 Uso Práctico: Auditoría / Hash / Normalización
```javascript
hooks: {
  beforeCreate: async (user) => {
    user.email = user.email.toLowerCase().trim();
    user.passwordHash = await bcrypt.hash(user.password, 10);
  },
  beforeUpdate: (user) => {
    if (user.changed('email')) user.email = user.email.toLowerCase().trim();
  },
  afterCreate: (user) => {
    AuditLog.create({ action: 'CREATE', table: 'USERS', recordId: user.id });
  }
}
```

### 9.4 Promesas y Async/Await
Todos los hooks soportan `async/await`. El ORM espera a que resuelvan antes de continuar la operación SQL.

### 9.5 Cancelar Operación
Lanzar un `Error` (o `ValidationError`) dentro de un hook `before...` cancela la operación SQL y hace rollback si hay transacción.

```javascript
beforeDestroy: (user) => {
  if (user.role === 'ADMIN') throw new Error('No se puede borrar admin');
}
```

## 10. Relaciones (Associations)

### 10.1 Definición
Se definen **después** de definir todos los modelos (ej. en `models/index.js`).

```javascript
// 1:N (HasMany / BelongsTo)
User.hasMany(Post, { foreignKey: 'userId', as: 'posts' });
Post.belongsTo(User, { foreignKey: 'userId', as: 'author' });

// 1:1 (HasOne / BelongsTo)
User.hasOne(Profile, { foreignKey: 'userId', as: 'profile' });
Profile.belongsTo(User, { foreignKey: 'userId', as: 'user' });

// N:M (BelongsToMany)
User.belongsToMany(Role, { through: 'UserRoles', foreignKey: 'userId', as: 'roles' });
Role.belongsToMany(User, { through: 'UserRoles', foreignKey: 'roleId', as: 'users' });
```

### 10.2 Opciones de Asociación
| Opción | Descripción |
| :--- | :--- |
| `foreignKey` | Nombre de la columna FK en la tabla **fuente** (HasMany/HasOne) o **target** (BelongsTo). |
| `as` | **Obligatorio**. Alias para `include` y getters/setters (`user.getPosts()`). |
| `targetKey` | Columna PK en el modelo objetivo (default: PK del target). |
| `sourceKey` | Columna PK en el modelo fuente (default: PK del source). |
| `onDelete` | `'CASCADE'`, `'SET NULL'`, `'NO ACTION'`, `'RESTRICT'`. Genera DDL en migraciones. |
| `onUpdate` | `'CASCADE'`, `'SET NULL'`, ... |
| `hooks` | `true`/`false`. Dispara hooks del modelo relacionado en `destroy` cascade. |

### 10.3 Eager Loading (`include`)
```javascript
const users = await User.findAll({
  include: [
    { model: Post, as: 'posts', where: { published: true }, required: false },
    { model: Profile, as: 'profile', attributes: ['avatar'] },
    { 
      model: Role, 
      as: 'roles', 
      through: { attributes: [] }, // Ocultar columnas tabla intermedia
      required: false 
    }
  ]
});
// user.posts -> Array<Post>
// user.profile -> Profile | null
// user.roles -> Array<Role>
```

### 10.4 Lazy Loading (Getters/Setters en Instancia)
```javascript
const user = await User.findByPk(1);
const posts = await user.getPosts({ where: { published: true } });
await user.addRole(adminRole);
await user.setRoles([adminRole, editorRole]);
await user.removeRole(guestRole);
await user.hasRole(adminRole);
```

## 11. Instancias de Modelo (Métodos de Instancia)

Una vez obtienes una instancia (`user = await User.findByPk(1)`):

| Método | Descripción |
| :--- | :--- |
| `user.get({ plain: true })` | Devuelve POJO (objeto plano) con valores. `plain: true` evita getters virtuales. |
| `user.set({ name: 'Nuevo' })` | Setea múltiples valores (usa setters virtuales). |
| `user.changed()` | `true` si hay cambios pendientes. |
| `user.changed('name')` | `true` si el campo 'name' cambió. |
| `user.previous('name')` | Valor anterior de 'name' (antes del set). |
| `user.save({ transaction, fields })` | Persiste cambios (UPDATE). `fields` limita columnas. |
| `user.update({ name: 'Nuevo' }, { transaction })` | Alias de `set` + `save`. |
| `user.destroy({ transaction })` | Borra registro (DELETE). |
| `user.reload({ transaction })` | Recarga datos desde BD (deshecho cambios locales). |
| `user.toJSON()` | Serialización automática para `JSON.stringify(user)`. |

## 12. Migraciones (CLI y Programático)

### 12.1 Estructura Archivo
```javascript
// migrations/001-create-users.js
import { Migration, DataTypes } from 'firebird-orm';

export default class extends Migration {
  async up(queryInterface) {
    await queryInterface.createTable('users', {
      id: { type: DataTypes.INTEGER, primaryKey: true, autoIncrement: true },
      email: { type: DataTypes.STRING(100), allowNull: false, unique: true },
      name: { type: DataTypes.STRING(50) },
      created_at: { type: DataTypes.TIMESTAMP, defaultValue: DataTypes.LITERAL('CURRENT_TIMESTAMP') }
    });
    await queryInterface.addIndex('users', ['email'], { unique: true, name: 'idx_users_email' });
  }

  async down(queryInterface) {
    await queryInterface.dropTable('users');
  }
}
```

### 12.2 `QueryInterface` - Métodos DDL
Todos los métodos retornan `Promise` y son transaccionales (se ejecutan dentro de la transacción de migración).

| Método | Firma |
| :--- | :--- |
| `createTable` | `(tableName, attributes, options)` |
| `dropTable` | `(tableName, options)` |
| `renameTable` | `(oldName, newName)` |
| `addColumn` | `(tableName, attrName, dataType)` |
| `removeColumn` | `(tableName, attrName)` |
| `changeColumn` | `(tableName, attrName, newDataType)` |
| `renameColumn` | `(tableName, oldName, newName)` |
| `addIndex` | `(tableName, attributes, options)` |
| `removeIndex` | `(tableName, indexName\|attributes)` |
| `addConstraint` | `(tableName, options)` (FK, Unique, Check, PK) |
| `removeConstraint` | `(tableName, constraintName)` |

### 12.3 Migrator (Programático)
```javascript
import { Migrator } from 'firebird-orm';

const migrator = new Migrator(sequelize, { migrationsPath: './migrations' });

await migrator.up();           // Ejecuta todas pendientes
await migrator.up({ to: '003' }); // Hasta migración específica
await migrator.down();         // Revierte última
await migrator.down({ count: 2 }); // Revierte 2
await migrator.status();       // Lista estado
```

## 13. Errores Comunes y Soluciones

| Error | Causa | Solución |
| :--- | :--- | :--- |
| `ConnectionError: connect ECONNREFUSED` | Servidor FB no accesible | Verificar host, puerto, firewall, `docker-compose up`. |
| `DatabaseError: Table X already exists` | Migración repetida / Test sucio | Usar nombres únicos en tests (`table_${Date.now()}`), limpiar `firebird_orm_meta`. |
| `ValidationError: allowNull violation` | Enviar `null` a campo `allowNull: false` | Validar input antes de `create`/`update` o permitir null. |
| `DatabaseError: Deadlock` | Concurrencia alta en transacciones | Implementar retry logic (`withRetry`), ordenar locks, reducir tiempo transacción. |
| `TypeError: Op.xxx is not a function` | Import incorrecto | `import { Op } from 'firebird-orm';` (no destructuring mal hecho). |
| `Numeric value out of range` | `Date.now()` en `INTEGER` PK | Usar `Math.floor(Math.random() * 1e9)` o `autoIncrement: true`. |
| `Name longer than database column size` | Nombre tabla > 31 chars (límite FB) | Nombres cortos: `t_${random}`. |
| `SET TERM not supported` | Crear SP via `queryRaw` | No soportado en wire protocol. Crear SP vía `isql` o script externo. |

## 14. Buenas Prácticas para Migración VB6 → Node.js

1.  **Mapeo 1:1 Primero**: Define modelos que reflejen **exactamente** la tabla legacy (`field`, `tableName`, `timestamps: false`, `freezeTableName: true`). No cambies la BD aún.
2.  **Tipos Críticos**: `DECIMAL`/`NUMERIC` → `string` en JS. Usa `get()` en el modelo para devolver `number` si tu lógica lo necesita.
3.  **Generadores PK**: Si usas `GEN_ID(GEN_X, 1)` en triggers FB 2.5, replica en `defaultValue: DataTypes.LITERAL('GEN_ID(GEN_X, 1)')`.
4.  **SPs Legacy**: No los migres a JS todavía. Úsalos vía `sequelize.queryRaw('SELECT * FROM SP_LEGACY(?)', { replacements: [params] })`.
5.  **Transacciones**: En VB6 usabas `StartTransaction` / `Commit`. Aquí: `const t = await Transaction.start(s); ... await t.commit();`.
6.  **Conexiones**: Configura `pool.max` según tu carga real (ej. 20-50 para apps web, 5-10 para scripts batch).
7.  **Tests de Integración**: Antes de tocar código legacy, escribe tests contra la BD real (`npm run test:int`) para asegurar que el ORM lee/escribe correctamente tus tablas actuales.
